Breaking Down Each Component (Practical Usage)

1. The "Root" Package (com.example.myapp)

  • Practical rule: Everything must be inside or below this package.
  • Why? Spring Boot's @ComponentScan starts scanning from this package by default. If you put a Service outside this folder, Spring won't find it, and you'll get cryptic NoSuchBeanDefinitionException errors.

2. The Main Class (MySpringBootApplication.java)

java

@SpringBootApplication  // This is a triple-annotation: @Configuration + @EnableAutoConfiguration + @ComponentScan
public class MySpringBootApplication {
    public static void main(String[] args) {
        SpringApplication.run(MySpringBootApplication.class, args);
    }
}
  • Practical placement: This file must be at the root of your package structure (directly under com.example.myapp).
  • Why? Because @SpringBootApplication scans all sub-packages (controller, service, repository) recursively. If you move this into a sub-folder, none of your beans get loaded.

3. The "Layered" Sub-Packages (Controller, Service, Repository)

This is the classic 3-tier architecture:

FolderPurposeKey Annotation
controller/Handles HTTP requests/responses (REST endpoints).@RestController, @RequestMapping
service/Houses business logic (calculations, validations, orchestration).@Service
repository/Talks to the database (CRUD operations).@Repository or public interface JpaRepository
model/Plain POJOs (Entities, DTOs).@Entity (JPA) or just plain Java classes.
config/Custom beans that override Boot's defaults (e.g., custom SecurityFilterChain, RestTemplate).@Configuration

Practical rule: Never put business logic in the Controller. Keep Controller thin (just parse input, call Service, return JSON). This makes unit testing easy.

4. The resources/ Folder (The Brain)

This is where your external configuration lives. It is not Java code; it is runtime data.

  • application.yml (or .properties): This is the single source of truth for environment-specific settings.
    • Example: server.port: 8081, spring.datasource.url: jdbc:mysql://localhost:3306/mydb.
    • Practical trick: You can have application-dev.yml, application-prod.yml and activate them using spring.profiles.active=dev.
  • static/: Put your frontend static assets here (CSS, JavaScript, images). They are served automatically at http://localhost:8080/css/style.css.
  • templates/: Put your server-side rendering HTML here (Thymeleaf or JSP). Boot auto-configures the ViewResolver to look here.
  • db/migration/: If you use Flyway, put your SQL migration scripts here (e.g., V1__create_users_table.sql). Boot runs them automatically on startup.

5. The test/ Folder (Parallel Structure)

  • It mirrors the main/java structure exactly.
  • Crucial file: MySpringBootApplicationTests.java – this is the "sanity check" test. It loads the entire Spring context to ensure your database connections and beans all wire up correctly.
  • Practical use: Always run this test before pushing to Git. If this test fails, your application won't even start in production.
